# 决策记录

更新：2026-10-28。本文件记录谁决定了什么及原因；业务规则的详细定义仍以[需求文档](微商系统课程设计-需求描述与技术讨论.md)为准。

## 1. 决策边界

| 类型 | 谁决定 | 如何处理 |
| --- | --- | --- |
| 功能增删、页面内容/主要布局/风格、注册或管理入口、真实支付等范围 | 用户 | 先展示具体方案、选项及影响，再按回复实施；不能以“技术细节”为由绕过 |
| 优惠叠加、计件、舍入、券门槛/返还、退货/退款、价格变化后的成交行为 | 用户 | 先用金额或操作样例讨论；未确认部分不能作为最终规则交付 |
| 语言、GUI 框架、构建工具、数据库访问方案、依赖与版本 | 代理，已获授权 | 结合课程约束选择并记录理由、限制和验证；不再要求用户先掌握技术术语 |
| 已确定契约内的类名、方法、拆分、参数校验、错误处理和必要测试 | 代理 | 可直接实现，验证后记入当日日志；不逐个打断用户 |
| 可能改变可见效果、业务含义、数据保留或已有兼容性的技术调整 | 用户决定影响，代理解释方案 | 即使属于技术改动，也需先说明影响并讨论；例如为解决并发问题改成忽略结算请求不可自行决定 |

不把所有代码修改变成审批。已经明确授权的事项继续执行；只有影响当前任务的未决产品问题需要先讨论，其他独立准备仍可推进。没有回复不代表同意。用户说“继续”只推进当前已说明的下一小步，不能据此批准全部待定业务规则。

### ADR-001 的理由与边界

两端统一语言，减少协议适配和构建差异；Swing 避免先引入额外 GUI 运行时，实际页面效果仍先给用户看。网络请求放到后台线程，界面更新遵守事件线程规则。[Oracle 线程说明](https://docs.oracle.com/javase/tutorial/uiswing/concurrency/)

SQLite 数据库只由服务端本机访问，降低课程演示的部署工作量；客户端通过 TCP 请求服务端。SQLite 同时只能有一个写者，需要短事务、忙等待和有限重试，并以并发测试验证边界。若实际需求超出这一范围，先说明改变的成本与影响，再调整数据库；不能直接声称它适合任意并发规模。[SQLite 适用范围](https://www.sqlite.org/whentouse.html)

JDBC/DAO 用来明确展示 SQL、映射和事务；原生 TCP 的长度前缀/UTF-8 JSON 沿用现有候选设计。Maven 统一构建、依赖与标准源码/测试目录。依赖数量和版本在首次使用前固定，GUI 外观不由框架选择自动定稿。[Maven 标准结构](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html)

这是针对当前课程范围的工程选择，不声称存在对所有项目都最好的技术栈。已有项目环境若不兼容，代理可在授权范围内选择兼容版本并记录；涉及业务、界面预期或范围变化时先讨论。

### ADR-007 的实现与验证

使用当前 JDK 的 PBKDF2WithHmacSHA256，固定 600000 次、16 字节随机盐和 32 字节结果，避免新增密码依赖或自行写散列算法；验证使用恒定时间结果比较。公开演示口令仅在 README 说明，账号种子存散列；没有口令/令牌日志。参数取自 [OWASP 密码建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，JDK 实现已实际运行，不声称 FIPS 认证。

会话生成 32 字节随机凭证，服务端仅内存存其 SHA-256 验证值，数量有界；用户身份/角色从数据库取得，停用、失效与错误角色均拒绝。客户端只在内存保留凭证；重连可续用，服务端重启或空闲 30 分钟失效。参照 [OWASP 会话建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) 选择高熵随机凭证和服务端校验，课程范围仍仅本机回环。

v1 先用参数化 VACUUM INTO 备份，再事务化新增账号与升级版本；原商品保留，迁移失败回滚。实际原库已升 v2，备份可读且商品逐字段相同；重复初始化不重置禁用/删除账号。[SQLite 一致性备份说明](https://www.sqlite.org/lang_vacuum.html)

新增实际复用的 desktop 模块供两端共用表单/登录小窗口。服务端只在测试范围依赖客户端，用真实客户端→Socket→SQLite 验证身份；运行包不引入客户端实现。137 项测试及真实 JAR TCP 鉴权通过，桌面检查游客/登录入口及管理锁定，表单用离屏渲染和事件测试检查；密码输入交互仍待用户试用，未冒称完成了桌面密码输入操作。

UI07 随后修正入口：登录前不创建管理窗口，AdminAccessGate 控制视图切换，ServerDesktop 统一程序生命周期，管理窗口构造还校验 ADMIN。S07a 合计 148 项通过且实际组件已渲染；后台监听和买家身份不因管理员退出/过期关闭。交付后用户在 C12 要求继续 S08，并通过 UI08 固定购物车行为；本轮总计 180 项通过，实际界面仍待用户试用。

S08 的技术实现基线见需求 §7.3：schema v3、原版本备份、同一 IMMEDIATE 事务、持久化版本和归属校验。超时/取消后要求刷新核对，禁止自动重放；实际 TCP 代理验证数据库提交后丢应答/取消，数量没有重复增加。技术实现没有改变 UI08 的数量/持久化含义；本轮不进入促销或成交。
