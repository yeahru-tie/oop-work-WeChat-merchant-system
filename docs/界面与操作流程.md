# S02：界面与操作流程

维护：2026-10-28，S02原始讨论日期2026-10-27。S11已实现，341项测试通过；管理员可设置商品活动/券，买家可领券/选券、部分勾选模拟成交并查询本人订单。实际交互待试用，精美UI仍在S14。

## 1. 两个程序各自负责什么

**买家客户端**是日常使用的购物窗口：看商品、管理购物车、确认报价、查订单、申请售后、接收站内消息。它负责交互和展示，不直接改数据库，不自行决定成交金额。

**服务端及简易管理窗口**由店铺侧运行：处理买家请求，保存数据，裁决金额和库存。已规划管理窗口查看交易/运行状态、受理售后、发布优惠公告，以及 UI10 商家促销管理。第一版不因这些入口自动扩展成完整商品后台、运营报表或多店平台。

演示时可以在同一台电脑先启动服务端，再运行两个买家客户端，使用不同账号。两个窗口共用店铺商品库存，但购物车、订单、券、售后和私人消息各自隔离。

## 2. 买家看到的入口

采用用户选择的“简洁的桌面购物软件风格”：一个主窗口、五个稳定入口，切换内容时不反复打开新业务窗口。登录使用独立小窗口；权限和身份校验仍在服务端。具体控件样式在实现后由用户查看，不能把本次文字确认说成实际界面已验收。

S04 当前在买家端底部提供“测试连接”和“取消”，服务端运行页显示本机监听地址。测试在后台等待，错误可见；成功文字代表最近一次探测结果，不代表已登录或可下单。这是 MVP 功能入口，不作为最终 UI 布局定稿。

S05 服务端启动先检查商品数据库，就绪后才显示监听成功；失败则提示检查数据库或端口，不接受请求。默认演示数据可用数据库脚本只读查看，商品页实际展示留在 S06。

S06 具体方案已按 UI04 确认：先用左图右文的图文列表，名称、价格、库存和缩略图一起显示，选中后在下方看较大图和说明；提供刷新/上一页/下一页，打开自动加载，本步只浏览。三款演示商品自带图片，缺图使用占位，图片标注为演示素材。后续可再讨论卡片网格，本次只实现这一种视图；实际页面效果仍待用户查看。

买家右上角“登录”打开独立小窗口，成功后显示名称并可退出。UI08 明确区别：游客浏览商品，点击加入或进入购物车先登录；成功回原位置，不自动加入。登录后自动加载、保存和管理本人购物车；退出/失效清除私人界面，重登/重启恢复，A/B 隔离。两个买家、一个管理员及暂不注册的范围不变；本人订单已实现，私人消息仍未实现。

商品页选择正整数数量加入，同品累加。UI11 购物车为图片卡片网格，卡内显示名称、单价、库存、数量、原价及预估小计、直降和折扣明细；步进或输入后回车/失焦自动保存，直接移除，无下方独立操作区。保存时禁用并标更新中；失败/未知清旧内容后先刷新。加入/增加校验库存但不扣库存，库存下降可减少/移除。底部三项合计换行展示，窄窗口可读；尚未开放成交。商品页仍为图文列表，显示活动及预估单价，统一网格和美化后置 S14。

UI13 修正商品页加入的库存拒绝恢复：明确 OUT_OF_STOCK 后自动只读更新购物车，成功即恢复加入按钮，保留选择及数量；用户调整新增量后可再次点击，不需要换页手动刷新，不会自动重发原加入。新量仍与车内同品累加；恢复读取失败/取消/身份失效，以及原写请求结果未知时，不解锁未经核对的内容。

管理端按 UI07 改为：启动只显示账号密码登录入口，没有运行状态/管理页，也没有游客入口。只有服务就绪且管理员验证通过，才创建管理窗口。口令错误、买家账号或仍在验证均留在登录入口；启动失败则禁用登录并显示通用错误。

退出管理身份或会话失效时，销毁当前管理窗口并回到登录入口，再次验证创建新管理窗口。后台商品服务仍保持运行，买家连接不受管理员退出影响；在入口点“退出程序”、关闭入口或关闭管理窗口，才结束整个服务端并释放资源。交易/售后、优惠公告功能本身仍未开放。

“促销管理”已加入管理员窗口。选商品后编辑每件直降、折数、北京时间起止及启停，可用任意正整数数量试算；预览读取现价、忽略时间/启停，并标明未发布。点击保存才更新配置，开始包含/结束不包含；新配置默认停用。买家下次刷新商品或购物车取得新优惠，配置可重启恢复。若版本冲突或保存结果未确认，禁用继续保存，先重新载入核对。退出/过期关闭本次管理页面与控制器，不影响买家服务；S11已验证历史订单快照不变，公告仍归S16。

开发者仍可用 README 的 `preview-promotion.ps1` 只读命令试算；它与商家保存活动是两个入口，不占库存或生成订单，不发布或改变买家优惠。商家正式活动由管理窗口保存；不自动预置三款示例。

短暂断线后可手动重连并继续使用有效身份；连接测试不延长登录。空闲 30 分钟或服务端重启后，会在校验身份时要求重新登录；管理员窗口还定时检查失效，不刷新空闲时间。关闭程序不保存登录状态/密码，明确退出撤销会话；退出网络未确认时也清除本地身份并提示。

| 入口 | 用户在这里做什么 | 重要的可见信息 |
| --- | --- | --- |
| 商品 | 图文浏览，选数量并加入本人购物车 | 缩略图、名称、价格、库存、较大图/说明及真实加入状态 |
| 购物车 | 当前改数量、移除、刷新；报价/券/成交后续开放 | 当前单价、数量、原价小计/合计、库存警示及失败后的核对提示 |
| 我的订单 | 查看成交记录和历史明细，从订单发起/查看售后 | 实际成交金额、订单状态、售后进度；申请不等于已退款 |
| 消息 | 查看订单/售后通知和优惠公告，跳到对应内容 | 未读数量、消息分类和时间、相关订单/商品入口 |
| 设置 | 切换主题、保存本机显示偏好 | 本地显示设置；退出账号操作保持容易找到 |

功能按开发计划逐步启用。骨架阶段可以存在入口，但未完成的功能明确标注未开放，不用假成功、假订单或虚构消息掩盖尚未接通的流程。

## 3. 一次购买如何完成

1. 买家登录，进入商品页，选择商品和数量，加入购物车。
2. 在购物车逐卡勾选商品和修改数量；初次/新增默认选中，合计及券门槛只算已选商品。服务端计算优惠并给出报价。
3. 点“确认模拟成交”先取得报价并弹出商品/优惠/最终金额，第二次确认才提交；返回不写订单。不接真实支付/地址/物流，重复点击由界面抑制且服务端防重。
4. 服务端完成事务后，界面显示订单号与成交结果，成功只移除选中条目，未选保留，可在“我的订单”查看历史详情。超时/取消保留原请求，按钮“核对本次结果”或“原键重试本次”不创建新购买，未核对前禁新成交。
5. 若库存、价格或优惠发生变化，清楚说明原因并给出新报价或失败提示，不默默按更高价格成交。

以上S09—S11行为已按UI12—UI17/UI19/UI20实现并验证。待核对记录保存在data/client-pending，重启/同账号重登恢复，不存密码或会话。暂未查到仍保留原编号，明确成功/失败后才清理；报价变化先刷新再由用户重新确认。

## 4. 售后如何完成

买家从自己的订单详情提交售后申请，并在订单内查看进度。店铺在服务端简易管理窗口受理；完成处理后，买家看到最终退款/退货状态并收到消息。

整单或部分退货、券是否返还、模拟退款步骤及受理权限属于业务规则，留在 S13 前具体确认。服务端窗口的存在不等于任何人都有管理权限，相关身份与授权也必须实现。

## 5. 消息窗口的第一版范围（用户已确认）

采用主窗口内的“消息”页面。普通消息以未读角标和列表呈现，不频繁弹窗打断操作。

| 类别 | 来源 | 查看后可做什么 |
| --- | --- | --- |
| 订单/售后通知 | 服务端根据本人订单成交和售后进度生成 | 查看文字摘要、时间，跳到有权限访问的订单详情 |
| 优惠公告 | 店铺人员在服务端管理窗口发布 | 查看活动说明，适用时跳到相关商品；订单入口与商品入口均须处理资源失效 |

软件运行且登录期间，后台定期检查新消息；退出期间的消息保留，下次登录后补收。第一版不要求退出软件后仍弹出系统通知，也不要求额外的实时推送通道。不能仅为这项功能把同步请求/应答整体改造成复杂异步架构。

消息及个人已读状态持久化，重新登录后未读状态可恢复。普通订单消息按用户隔离；店铺公告可以面向全部买家，但每个用户的已读状态独立。轮询周期、消息标识、列表/标记已读接口以及可靠生成方式在 S16 实施前固定并验证；同一条消息不因多次检查反复新增。

**公告内容不等于优惠规则。** 发布“某商品有优惠”不会自行改变售价或核销资格；实际生效条件仍取自服务端促销配置与结算校验。普通公告失效不能影响已成交订单，消息跳转也不能绕过订单权限。

不纳入本次范围：聊天、客服会话、图片广告编辑器、广告推荐算法、短信/邮件/微信通知、软件退出后的系统通知。若以后需要，先说明成本和影响再讨论。

## 7. S10 优惠券流程（已实现，待实际交互验收）

UI16/UI17确认：商家创建全店满减券活动，填写名称、门槛、减免金额、北京时间起止和发放总量。保存草稿后再发布，发布锁定门槛、减免、有效期和总量；想改条款新建券，发布后只暂停/恢复领取，不撤回已领券。领券与用券共用起止，开始包含结束不包含。

买家在购物车打开“领券/选券”，每人每种限领一张；显示本人券及不可用原因，可手选一张或不用。先算商品直降/折扣，再按优惠后合计判断满减门槛并抵扣，最低0。例如商品优惠后162元，用满150减20为142元。

改数量或刷新后重算；所选券过期或不达门槛时明确提示重选或选择不用，不静默变成无券金额继续。领取只产生本人券并占用发放量，报价不核销或扣库存；S11在最终确认后同事务成交。参数、发布锁定和失效交互均已接入真实持久化与TCP，完整窗口效果仍待试用。

当前入口：管理员“优惠券管理”左侧分页选择券，右侧编辑草稿，依次保存/发布；有未保存编辑不能发布，已发布字段变灰，只能暂停/恢复领取。新建券不会自动保存或发布，结果不明/版本冲突先重新载入。买家购物车顶部“领券/选券”切到同页内面板，“领券活动”领取、“我的券”选用或不用，再“返回购物车”；保留原卡内数量/移除，底部列出原价、商品优惠、券抵扣和应付预估。领取不自动选用，关闭程序不保存选择。

“刷新报价”使用当前购物车及原所选券；活动时间边界已到时隐藏旧应付并提示刷新。领取结果未确认则先刷新列表核对，失败/取消/退出清旧券页和报价；会话失效返回登录，其他账号不能看前一账号的券。现在没有“确认成交”按钮。
