# S13：售后流程与验收

2026-10-28，按C22一轮完成S13.2—S13.4，沿用UI22/UI23。完整离线verify通过402项（协议105、desktop3、客户端54、服务端240），比S13.1新增32项。售后已接通，实际原生窗口体验仍待用户试用。

## 如何试用

完全关闭旧服务端和买家程序，再按[README](../README.md)启动新版。仅退出账号不会重新加载JAR。已知旧库先生成原版本备份再升级v7，已有v7只验证；不要删除数据库或待核对记录来恢复功能。

1. 买家登录，在“我的订单”刷新并选择一单，点击“查看详情”；填写1—500字原因，点“申请整单退货”。只允许申请本人已成交订单，申请不会立即退款或补库存。
2. 管理员在服务端“交易与售后”选择交易并载入，查看原成交、最新申请和历史。可“批准退货”，或填写1—500字说明后“拒绝申请”。批准后仍是处理中，退款/库存没有变化。
3. 模拟收到全部退货后，管理员明确点击“确认退货完成（模拟退款/补库）”。此时同一事务完成模拟退款、补回原数量及更新状态；重复完成返回原结果，不再退款/补库。这里只模拟，不对接支付或物流。
4. 买家点“刷新售后”查看审核/完成时间、原因/拒绝说明及退款金额。退原订单全部商品和原实付，已用券不返还；例如实付142元就退142元，0元订单退款0元且照常补原数量。现价、活动、券到期不改变退款依据。
5. 拒绝后可重新填写原因申请，保留每次记录；同一订单同时最多一笔处理中，完成退款后不能再次申请。历史支持分页，管理员操作针对最新申请，不能从旧历史页重复处理。

状态：订单 `COMPLETED → RETURN_REQUESTED → REFUNDED`；申请拒绝时订单回到COMPLETED。售后 `REQUESTED → APPROVED → COMPLETED` 或 `REQUESTED → REJECTED`。订单在批准后仍显示退货处理中，售后明细说明已批准、待明确完成。成交金额保持历史原值，退款另有记录，不把原实付改成0。

## 未知结果与恢复

买家提交前原子保存原returnKey/orderId/reason至 `data/client-returns/`，只含公开账号标识和原请求，不存密码/会话。取消、断线、关窗或服务端重启后，同账号登录可“核对本次申请”或“原键重试申请”；暂未查到不表示肯定未提交，不自动换键新申请。当前有效界面接收已核对终态后才后台清记录，短暂本地整理阶段不可取消成未知。记录损坏保留并阻止新申请，不能直接删除未知记录后重申。

管理员写操作结果未确认或状态冲突时，禁用继续处理，先重新载入核对；管理服务逐次验证当前管理员和所见版本。商品缺失或补库超出支持上限时，整次失败并保留已批准状态供核查，不自动重建商品或截断库存。技术限制不会被显示为已退款。
