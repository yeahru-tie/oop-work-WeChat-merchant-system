# S14/S16 主题与站内消息验收

2026-10-28，按 C23 合并推进 S14/S15/S16；UI24、UI25 已由用户明确采用，UI18 本期保持全店券，商品排除留作后续扩展。本材料区分自动验证与实际用户验收。

## 实现范围

- UI24：暖白/蓝绿色浅色与深蓝灰/柔和青色深色两套主题。商品改为响应式卡片网格，继续缓存图片、分页、说明与卡内数量；购物车保留勾选、数量自动保存、卡内移除及结算。两端复用 desktop 的主题、字体、按钮、页签与卡片，不改变业务模型。
- 主题偏好在后台原子写入本机 data/client-theme.txt 或 data/server-theme.txt，启动时读取；不同应用独立保存，账号切换不改变主题。文件缺失/损坏使用浅色且不覆盖原文件，保存失败明确提示。
- UI25：成交、售后申请/批准/拒绝/完成在原业务事务写通知，事件键唯一；SQL 失败整次回滚，重复结果不重复发通知。升级前历史交易不补造消息。
- 管理端“优惠公告”发布纯文字，标题1—80字、正文1—2000字，可填存在的商品编号；全部买家含以后登录账号可见。发布后无修改/撤回入口，重试原发布标识必须内容一致。公告不配置真实活动。
- 买家消息页按订单/售后/优惠公告显示类别、时间、正文及未读角标；打开消息即标为本人已读。订单跳转仍通过本人订单接口，商品通过原目录分页定位。消息、已读状态持久化，账号退出/失效清理私人内容。
- 登录后空闲时立即检查，此后每15秒检查；复用原串行网络队列。忙碌、成交确认或未核对提交期间不自动插入检查，消息读取使用peek不延长原30分钟空闲会话。没有额外连接、聊天或退出后系统通知。

## 手动查看

完全关闭旧两端后构建并启动新版；服务端先登录管理员。“显示设置”切主题，“优惠公告”发布带商品编号的通知。买家登录后打开“消息”，检查未读、打开标读及关联跳转；换买家 B 验证其阅读状态独立。再完成一次模拟成交和一次售后，核对通知与订单状态。

主题、窗口大小和卡片排布可继续按实际反馈调整；当前实现完成不等于用户已接受最终效果。界面预览见[预览说明](界面预览.md)。
