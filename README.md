# 微商系统课程设计

面向对象程序设计课程的桌面 C/S 微商系统，保留第一至第六篇报告及需求设计文档，按可验收的小步骤开发。

当前 S11 已完成，341 项测试通过：购物车可勾选部分商品、核对金额并二次确认模拟成交，订单/库存/券同事务提交，未选商品保留；支持本人历史订单及未知结果恢复。S09/S10 管理、领券和混合报价保留，最终精美 UI 留到 S14。

## 使用本地开发工具

本机已在 `.tools/` 准备 Temurin JDK `25.0.5+8` 和 Maven `3.10.0`。该目录不进入 Git，新克隆的仓库需要先准备工具：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-toolchain.ps1
```

准备完成后，在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\maven.ps1 --version
```

入口自动使用固定版本和仓库内 Maven 依赖缓存，不修改系统环境或永久执行策略。`--version` 仅检查工具链；更多交互终端用法见环境文档 §5。

## 构建与启动

在仓库根目录执行构建；首次需要联网获取 Maven 插件，缓存放在 `.tools/m2/repository/`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\maven.ps1 --batch-mode --no-transfer-progress verify
```

生成 `client/target/merchant-client.jar` 和 `server/target/merchant-server.jar`，各自包含独立入口、共用协议和 Gson 运行依赖；服务端另含 SQLite JDBC、驱动服务注册和初始化资源。修改源码后重新运行构建，启动脚本只运行现有 JAR，不自动构建。

在两个 PowerShell 终端分别启动。终端等待对应程序退出后返回；管理窗口切回登录入口不会结束服务端进程。

终端一，启动服务端管理员登录入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -App server
```

终端二，启动买家端：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -App client
```

服务端启动后只显示“管理员登录”，不会显示管理页或运行状态。使用下方管理员账号验证成功后，才创建管理窗口；此时“运行状态”显示 `商品数据库已就绪；通信已启动：127.0.0.1:18765`。初始化失败时只显示禁用登录的错误入口，不回退到游客管理窗口。

买家端打开后自动加载商品，选中一项查看较大图和说明；“刷新”重载当前页，每页最多 20 条，按结果启用上下页。缺图显示占位图；三款内置图片为 AI 生成演示素材，已在页面标注。

服务端未启动、超时或断开会显示失败并清除本次旧结果；恢复服务后按按钮重试。购物车写入结果未确认时须先刷新核对，不自动重复加入。等待时可用底部“取消”，窗口仍可操作；“测试连接”保留独立探测功能。关闭买家窗口释放 Socket 和后台任务；本人订单已可查询，消息和设置仍为占位入口。成交未知结果另按下方S11流程核对。

买家端右上角“登录”打开独立小窗口，成功后显示当前买家，并可“退出登录”。服务端登录入口只接受管理员；口令错误、买家账号或尚在验证时均不创建管理窗口。管理员进入后，交易/售后与公告仍明确尚未实现。

“退出管理身份”或管理员会话失效会销毁管理窗口并返回登录入口，重新验证后创建新管理窗口。后台商品服务与管理窗口身份分开：返回登录不影响买家连接；在登录入口点“退出程序”、关闭登录入口或关闭管理窗口，才关闭整个服务端。旧进程不会热更新，修改后需重新启动服务端查看新入口。

若默认端口已占用，在两端启动命令都追加同一个 `-Port 18766`。目前只监听本机回环地址，不支持直接从另一台电脑连接，也不更改系统防火墙。

连接检查使用 `1000 PING → 2000 PONG`，只验证通信，不代表登录或交易已就绪。界面展示最近一次测试结果；服务端关闭或连接空闲超过 30 秒后，下次探测可能提示断开，再点测试会重新建立连接，不自动重放请求。完整帧/字段/错误规则统一见[需求文档 §6](docs/微商系统课程设计-需求描述与技术讨论.md)。

当前验证：离线 `verify` 成功，协议96、共用表单3、客户端51、服务端191，共341项，无失败/错误/跳过。新增部分成交、历史快照、报价变化重确认、库存/券/订单回滚、同键并发防重、有限库存竞争、跨账号拒绝、丢应答/取消及重启恢复、v5备份升级。实际JAR的TCP流程和组件渲染已检查，报告在各模块 `target/surefire-reports/`。完整原生窗口交互待用户试用。

演示图片、匹配方式和实际生成提示词见[图片说明](client/src/main/resources/products/README.md)。图片解码在界面事件线程之外进行，列表使用缓存；以后改卡片展示可复用现有数据与后台控制，本次未增加第二种布局。

## 基础购物车（S08/S08a/S08b）

1. 游客能浏览图文商品；点击“加入购物车”或进入“购物车”时先登录。成功后保留原页面/商品选择，需自己再次点击加入，不自动执行游客操作。
2. 登录后自动读取本人购物车。商品页输入数量并加入，同品累加；购物车按窗口宽度显示卡片网格，包含同款图片、名称、单价、库存、数量及小计。直接在对应卡片步进修改数量，或输入正整数后按回车/移开焦点自动保存；点卡内“移除”直接删除，不设置下方独立操作区。加入/增加时校验库存，不预占或扣减库存；库存下降可减少或移除。
3. 卡内显示当前单价、数量、原价小计、直降/折扣优惠及预估小计，底部合计按勾选商品计算；每次刷新/数量保存取得当前优惠，不锁价，成交须二次确认。最多 100 种商品，达到上限明确提示；金额精确计算，不受大整数溢出影响。
4. 退出立即清除私人界面，重新登录或重启服务端后恢复本人购物车。可分别用 A/B 账号启动两个买家程序，检查互不混用。
5. 商品页加入时收到明确“库存不足”，会只读更新购物车并恢复加入按钮，保留当前选择/数量；调整新增数量后再次点击即可，不必切到购物车手动刷新，原加入请求不会自动重发。同品新增量仍与购物车已有数量累加，不能超过库存。
6. 保存期间显示更新中并禁用重复操作；其他失败、版本冲突、超时/取消/应答丢失时，仍清除旧内容并按提示先刷新核对；库存拒绝后的自动读取若失败，也需先恢复连接/身份再刷新。商品页当前仍是图文列表，统一网格方向已记录到后续 UI 调整。

## 商家设置促销（S09）

重新构建后重启服务端和买家端。服务端用管理员账号登录，进入“促销管理”：

1. 选择商品，填写每件直降金额与折扣；直降填 0 表示不直降，10 折表示不打折，可组合使用。
2. 填写北京时间起止，如 `2026-10-28 08:00:00`；开始包含、结束不包含，结束须晚于开始。新配置默认不启用。
3. 调整试算数量，点“预览未保存参数”查看每步优惠；预览不受启停/时间限制，也不发布或扣库存。
4. 勾选/取消启用，点“保存配置”才更新活动。买家刷新商品或购物车后看到生效优惠；尚未到开始、已结束或停用时按原价。

每商品一组配置；若提示配置已变化或保存结果未确认，先点“重新载入”核对，再编辑保存。保存可重启恢复。没有自动预置活动；优惠券和模拟成交见下文，公告后续实现。

## 优惠券与混合报价（S10）

请完全关闭旧服务端和买家程序，再按上方命令启动新版；仅“退出管理身份”不会重新加载程序。服务端登录后有“优惠券管理”标签。

1. 管理员点击“新建券”，填写名称、满减门槛、减免金额、北京时间起止和总量，先“保存草稿”，再“发布券”。草稿买家不可领，发布后条款锁定；未保存的编辑须先保存才能发布。
2. 可暂停/恢复领取，已领券仍按原条款使用至到期。修改条款请新建券；名称1—80字符、门槛≥0、减免>0、最多两位小数，总量为正整数。领券和用券共用起止，开始包含、结束不包含。
3. 买家在购物车点“领券/选券”，切到“领券活动”领取，每人每种限领一张；切“我的券”可看本人券及不可用原因，手动使用一张或选择“不用优惠券”。领取不会自动选用。
4. 服务端先算商品直降/折扣，再按优惠后合计判断券门槛和抵扣，最低0元。例如200元商品优惠至162元，再用满150减20券，应付预估142元。
5. 修改数量、刷新购物车或“刷新报价”后重算。所选券失效时不显示无券应付，须重新选券或明确不用；活动时间边界到达也须刷新报价。预估不锁价，选券/报价不消耗券或扣库存；只有二次确认后的成交事务才核销与扣库存。

若领券结果未确认，先刷新券列表核对，不反复点击领取。个人券和商家配置均可重登/重启恢复，不预置默认券；下次登录仍须手动选券。

## 勾选结算与本人订单（S11）

请完全关闭旧买家和服务端程序，再用启动命令重新打开；只退出账号不会加载新JAR。新版服务端遇到已知旧库会先备份，再升级到v6。

1. 购物车每张卡片有“本次结算”复选框，初次全选、新增默认选中。合计、券门槛与抵扣只算已选商品；数量和移除仍在卡内操作。
2. 点击“确认模拟成交”先获取当前报价，再弹出所选商品/数量、优惠和最终金额；点“返回，不成交”不写订单。再次确认才提交，无真实支付、地址或物流。
3. 成功后显示订单号，扣减选中库存、核销所选券，并仅移除本次已选条目。未选商品保留；“我的订单”可分页并查看成交时的商品、优惠与金额，后续改价不改旧单。
4. 报价、活动、券资格或购物车变化时本次不成交，刷新后须再次核对确认；库存不足或任何失败均不部分扣库存/用券。
5. 超时、取消等待或断线显示“结果待核对”，先点“核对本次结果”；暂未查到也不表示没有成交，可继续核对或点“原键重试本次”。这两个操作一直使用原结算编号，期间禁止新购买。

提交前买家将原请求原子保存在 `data/client-pending/`，只含公开账号标识、结算编号和勾选/报价参数，不存密码或会话。关闭程序或服务端重启后，同账号登录会恢复核对；记录损坏时保留文件并阻止新成交，不要直接删除未知记录后重买。核对到最终成功/明确失败才清理对应记录。售后和管理员交易受理入口仍在后续步骤。

“某些商品不能用券”已登记为后续需求，尚未实施；当前全店券没有自动增加商品限制。

## 单品促销只读试算（开发工具）

构建后可按商品编号、数量和显式参数预览，不需要打开窗口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\preview-promotion.ps1 -ProductId 1001 -Quantity 2 -Reduction '1.00' -Discount '9'
```

读取当前商品单价，逐件先直降再打折，四舍五入到分后汇总。对于未改价的演示笔记本（12.90 元），上述结果为原价 25.80 元 → 直降后 23.80 元 → 预估 21.42 元，优惠合计 4.38 元；各步优惠额会单独显示。

`-Reduction` 为每件直降金额（元），非负且最多两位小数，默认 `0.00`；超过单价时最低零元。`-Discount` 为大于 0 至 10 的折数，最多两位小数（如 `8.85`），默认 `10.00` 即原价，暂不支持 0 折。数量须正整数，按整数分精确计算，大总额不会用浮点数或溢出。

这是本地开发核对工具，库存仅作只读参考。预览不保存/发布活动、不占库存、不创建订单或核销券；商家管理和买家真实活动已经接入同一计算器，但该命令本身不会改变活动或买家报价。

可加 `-DatabasePath 'data/demo.db'`，相对路径从仓库根目录计算。命令只读已有最新模式库，不会创建缺失库或自动迁移。Java 预览程序成功返回 0，参数无效返回 2，数据库不可用/模式未就绪返回 1；PowerShell 会先拒绝类型或范围不合法的脚本参数。尚未建库时先使用下方数据库初始化命令准备。

## 演示账号与登录（S07）

以下是公开的课程演示口令；账号只在首次创建 users 表时写入。数据库和 [账号种子](server/src/main/resources/db/demo-users.json) 仅保存加盐散列，启动不会重置已修改、禁用或删除的账号。

| 入口 | 账号 | 公开演示口令 |
| --- | --- | --- |
| 买家端 | `buyer_a` | `BuyerA#2026!` |
| 买家端 | `buyer_b` | `BuyerB#2026!` |
| 服务端管理员登录入口 | `shop_admin` | `ShopAdmin#2026!` |

账号和口令区分大小写，当前不提供注册或改密码页面。游客能看商品；加入或进入购物车时弹出登录，登录后能保存和管理本人购物车，账号间隔离。管理端没有游客入口；管理员账号不能在买家入口获得买家身份。

登录状态只保存在内存，关闭程序不记住状态/密码。短暂断线后按按钮重连可继续使用有效会话，空闲 30 分钟或服务端重启后须重新登录；“测试连接”不会延长登录时间。明确退出会撤销会话；若退出请求未获确认，仍清除本地身份并给出提示，服务端原会话会超时失效。登录/退出均不自动重发。

## 商品数据库与只读检查（S05）

服务端默认使用仓库根目录的 `data/merchant.db`。第一次启动会在一个事务中建表、写入三条演示商品及归属/版本标记；以后启动只验证，不重置价格/库存，也不补回已删商品。种子源文件为 [demo-products.json](server/src/main/resources/db/demo-products.json)，修改种子只影响今后创建的空白库，不覆盖现有库。演示目录不是正式商品清单。

当前代码模式为v6，包含商品、账号、购物车、商品活动、券活动/个人券、订单/历史明细和成交结果记录。遇到已知v1—v5，先在同目录生成 `merchant.db.v<原版本>-<随机标识>.db` 一致性备份，再单事务升级；保留现有商品、账号、购物车、活动及已领券，失败回滚。启动/init才迁移，list/只读试算不迁移。本轮未写本机默认库；首次新版启动会备份升级，已有v6重复启动只验证、不重置。迁移测试使用独立临时库，数据与备份都不进入Git。

构建后也可单独初始化或查看，无需打开窗口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\database.ps1 -Action init
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\database.ps1 -Action list
```

`init` 可重复执行，随后打印第一页；`list` 只读查询，不创建缺失数据库。两种命令都返回 JSON 商品页，默认最多 20 条；运行数据不提交 Git。数据文件存在但归属/版本不认识或必需表/列缺失时会拒绝使用，不能靠删除数据库解决：先保留文件、核对指定路径，再评估迁移。

服务端与数据库命令均可追加 `-DatabasePath 'data/demo.db'`；相对路径始终从仓库根目录计算。启动脚本为服务端配置 Java 本地库访问参数，数据库脚本还临时统一 UTF-8 输出并恢复控制台编码，无需系统 SQLite 或额外安装 GUI 工具。

服务端已支持 `1001 → 2001`：请求 body 为可选 `limit`（1—100）、`offset`（非负整数），返回 `items/limit/offset/hasMore`。金额使用整数分，例如 1290 表示 12.90 元。参数错误与数据库故障有明确失败应答，不伪装为空列表。完整约定见[需求文档](docs/微商系统课程设计-需求描述与技术讨论.md)。当前仅供本机 MVP 只读验证，正式登录访问策略在 S07 确定。
