# 开发日志

这里保留实际工作和交接信息。项目当前状态看[开发计划](../docs/开发计划.md)，需求口径看[需求文档](../docs/微商系统课程设计-需求描述与技术讨论.md)，重要选择看[决策记录](../docs/决策记录.md)。

## 记录规则

- 文件按 `YYYY-MM-DD.md` 命名，使用 Asia/Shanghai 日期。当日第一次实际开发或修改仓库时创建，同日后续工作继续追加会话条目，不覆盖已有内容。
- 本仓库的“自动记录”指代理每次实际工作后按 `AGENTS.md` 维护日志；不是无人运行时也会执行的每日定时任务。无开发不创建空日志，普通问答也不必生成日报。
- 开始时读取最近一份日志，找回未完成项、用户反馈和待决定问题。跨日把仍未完成项带到新日志，保留原任务编号，不因换日勾选完成。
- 结束前记录实际改动、验证证据、遗留问题和下一项任务；同步任务板。日志维护属于本轮交付的一部分，不要求用户每次提醒。
- 一项工作区分“已实现”“已验证”“待用户验收”。用户明确反馈后再记为已接受；代理不能代替用户勾选产品效果验收。
- 测试记录保留必要的命令、结果和限制，不贴大量输出、密码、令牌或个人信息；没有运行就写未运行。
- 如果工作中断未能收尾，下次以文件和 Git 状态核对实际进展，再补记并注明“补记”，不编造过去的运行结果。

日志是交接记录，不是全程聊天转录。只记录足够让下一轮知道“做到哪、为什么、还缺什么”的信息。

## 当日条目模板

新文件首行是日期；每轮追加一节，序号从 01 递增。可直接采用以下结构：

```markdown
# YYYY-MM-DD 开发日志

## 会话 01：任务编号与名称

### 本轮目标与边界

- 本轮目标：
- 本轮不涉及的后续事项：

### 已完成

- 实际结果与涉及文件：
- 实现状态：未开始／进行中／已实现
- 验证状态：未运行／通过／失败／受限
- 用户验收：不适用／待验收／已接受（记录反馈依据）

### 验证记录

- 命令或查看方式、结果、未验证内容：

### 决定与问题

- 新授权/决定：引用决策记录编号；没有则写无。
- 待讨论问题或阻碍：

### 待办与下次入口

- [ ] 下一项最小任务（沿用计划编号），开始前提：
- [ ] 尚未完成的当前任务：
```
